# 道路巡查 Demo

以 NestJS 微服務 + PostGIS + React 打造的公共工程巡查系統示範專案。

從車機上傳一筆案件開始，經過去重、非同步補資料、派工、施工回報、驗收，到報表產出與即時看板 —— 這條路徑上會遇到的工程問題，都在這個 Demo 裡有對應的處理。

> **所有資料皆為合成**，公司、機關、案件、座標都是虛構的，與任何實際專案無關。

---

## 這個 Demo 想示範什麼

不是「能跑的 CRUD」，而是幾個在真實系統裡真的會痛的問題：

| 問題 | 這裡的作法 |
|---|---|
| 車機在隧道裡收不到回應就重送，同一筆案件來了三次 | [三層冪等](#冪等性三層) |
| 逆地理編碼要三秒，但上傳不能等 | 丟進 BullMQ，由獨立的 worker 行程處理 |
| 一份三萬列的 Excel 會把 event loop 佔住好幾秒 | 報表另開一個行程，併發數與記憶體上限都不同 |
| 每日備份不能因為 API 開了三個實例就跑三次 | 排程獨立行程 + Redis 分散式鎖 |
| 誰把案件狀態改掉了？改之前長什麼樣？ | [版本化歷程](#版本化歷程)，可回溯、可還原、只增不改 |
| 平台開通給廠商、廠商再開給外包，而且不能越級 | [三層組織](#三層組織與授權傳遞)，授權只能向下傳遞 |
| 白天在工地看不見深色畫面，深夜盯白底也不合理 | 日夜佈景切換，狀態色兩套，選擇記在裝置上 |
| 掃清單時想先看照片再讀欄位 | 清單縮圖，點開進檢視器：滾輪縮放、拖曳平移、鍵盤翻頁 |
| 現場師傅與辦公室要即時溝通，但斷線不能漏訊息 | WebSocket 雙向通訊，訊息落地資料庫 |
| 出事時要能查「這筆案件經過了哪些服務」 | Grafana + Loki 集中日誌 |
| 這條軌跡有沒有經過那幾個坑洞？ | 單一地圖 + [圖層登錄表](#一張地圖多個圖層)，圖層可疊看 |
| 上千個點疊成一片，看不出哪一區嚴重 | 三種渲染模式：案件 / 聚合 / 熱點 |
| 全區圖層每次平移都重載幾 MB | PostGIS 直出[向量圖磚](#向量圖磚)，單格 42 KB |
| 憑證過期時使用者卡在壞掉的畫面 | 全域 401 處理 + 主動續期 |

## 架構

六個行程，各自一個容器。**分開的理由是「壞的方式不同」**：

```
                      ┌─────────┐
   瀏覽器 ──────────▶ │  nginx  │ 靜態檔 + 反向代理
                      └────┬────┘
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │   api    │ │  tiles   │ │  (靜態)  │
        │ HTTP+WS  │ │  圖層    │ └──────────┘
        └────┬─────┘ └────┬─────┘
             │            │
      ┌──────┴────────────┴──────┬──────────────┐
      ▼                          ▼              ▼
 ┌─────────┐              ┌───────────┐  ┌───────────┐
 │  Redis  │◀─── 佇列 ────│  worker   │  │ scheduler │
 │ 佇列/鎖 │              │ 案件處理  │  │  11 支排程 │
 │ 事件匯流│              └───────────┘  └───────────┘
 └────┬────┘                     ▲
      │                    ┌─────┴──────┐
      │                    │report-worker│ Excel / Word
      │                    └─────────────┘
      ▼
 ┌──────────┐  ┌─────────┐  ┌──────────────────┐
 │ PostGIS  │  │  MinIO  │  │ Loki + Grafana   │
 └──────────┘  └─────────┘  └──────────────────┘
```

| 行程 | 職責 | 為什麼獨立 |
|---|---|---|
| `api` | 對外 API、WebSocket、事件訂閱 | 使用者等在螢幕前，要快 |
| `tiles` | 圖層(GeoJSON + Redis 快取) | 一次吐幾 MB，序列化會佔住 event loop |
| `worker` | 案件佇列(逆地理編碼) | 會逾時、要重試 |
| `report-worker` | 報表佇列(Excel / Word) | 一份報表吃幾百 MB |
| `scheduler` | 11 支排程 | 只能有一份在跑 |
| `nginx` | 靜態檔、反向代理 | — |

### 示範帳號

登入要三個欄位：**單位代碼 / 帳號 / 密碼**。密碼皆為 `Demo1234`。

| 單位 | 帳號 | 角色 | 能做什麼 |
|---|---|---|---|
| `ROOT` 平台管理 | `root` | 系統管理員 | 開通廠商單位的權限與人員額度 |
| `DEMO` 廠商單位 | `admin` | 系統管理員 | 全部；並可開通外包單位 |
| `DEMO` | `inspector` | 巡查員 | 建案件、派工、報表 |
| `DEMO` | `worker1` | 施工人員 | 回報施工進度 |
| `DEMO` | `viewer` | 檢視者 | 唯讀 |
| `SUB01` 外包單位 | `suboffice` | 系統管理員 | **只有被開通的七項** |
| `SUB01` | `subworker` | 施工人員 | 回報施工進度 |

`suboffice` 值得試一次：它的角色是「系統管理員」，但公司只被開通七項權限，
登入後拿到的是兩者的交集 —— 側邊欄少了一半，派工與驗收的按鈕不會出現。
用 `DEMO/admin` 到「系統管理 → 下層單位」改開通內容，再重新登入就看得到差別。

## 幾個值得看的設計

### 冪等性三層

車機在收不到回應時會自動重送。同一筆案件可能連來三次，而三次都不能變成三筆資料：

1. **HTTP 層** — `Idempotency-Key` 表頭 + Redis `SET NX`，重送直接回放第一次的回應
2. **佇列層** — BullMQ 的 `jobId` 綁定案件外部編號，重的活只會做一次
3. **資料庫層** — `(dt_record, img_detect, crack_id)` 與 `external_id` 唯一鍵

Redis 會被清空、去重視窗會過期，**第三層是唯一不會消失的保證**。

同樣的想法也用在排程（Redis 鎖 + 逾時自動釋放）與報表（相同條件沿用同一筆工作）。

### 版本化歷程

破壞案件、派工單、標案、檢測案件**共用同一組端點** —— 版本化的規則對四者是一樣的，
拆成四套只是同樣的邏輯抄四遍。主鍵是 `(case_type, case_id, version)`。

每次變更寫一筆，含**當下的完整快照**、**這次改了哪些欄位**，以及誰、什麼時候、
從哪個 IP、是人改的還是排程改的：

- 時間軸：`GET /history/CASE_PATROL/:id`
- 看任一版本：`GET /history/CASE_PATROL/:id/version/:v`
- 比較兩版：`GET /history/CASE_PATROL/:id/diff?FROM=1&TO=3`
- 還原：`POST /history/restore`
- 稽核（跨實體）：`GET /history/audit?DATE_FROM=…&OPERATOR_ID=…`

還原**不會刪除後續版本** —— 它本身也是一筆新版本。能被抹掉的歷程就不算歷程。
而且只還原人改得動的欄位：座標、照片、外部系統 id 不還原，
那些是「這筆資料是什麼」而不是「有人改過的內容」。

存快照而不只存差異，是因為「要看第 30 版長什麼樣」不該需要從第 1 版重放 29 次。

版本號在交易裡計算、而且是主鍵的一部分：兩個同時發生的變更不可能拿到同一個版本，
撞號會直接失敗，而不是靜靜覆蓋掉別人的那一版。

### 三層組織與授權傳遞

```
平台管理  ──開通模組與額度──▶  廠商單位  ──再開通子集──▶  外包單位
```

兩條規則撐起整個機制：

- **只看得到自己的子樹** —— 廠商查不到平台，也查不到別的廠商。
  不是畫面上的隱藏：查詢本身以遞迴 CTE 收斂，範圍外一律回 404。
  回 403 等於承認「有這個公司但你不能碰」，本身就洩漏了它的存在。
- **開不出自己沒有的權限** —— 上層的授權是下層的上限。
  少了這條，廠商可以自己開一個全權限的外包單位。

**使用者權限 = 角色動作 ∩ 公司開通**。這是開通機制唯一真正生效的地方 ——
示範資料裡外包的 `suboffice` 角色是「系統管理員」，登入後只拿得到被開通的七項。

收回權限會**往下遞迴**，否則會留下「上層沒有、下層卻還有」的孤兒授權。

### 分表：誰在寫，決定放哪張表

案件拆成三張、派工單拆成四張，界線是「誰在寫、寫多頻繁」：

| 表 | 誰在寫 | 頻率 |
|---|---|---|
| `patrol_cases` | 車機／APP | 每天幾千筆，寫完就不動 |
| `patrol_case_addresses` | 逆地理編碼的 worker | 案件建立後才補上 |
| `patrol_case_statuses` | 承辦、主管 | 一筆案件被改很多次 |

合成一張的代價很具體：車機的大量寫入會跟承辦的編輯搶同一列，
而且地址還沒補到時，案件會因為欄位不完整而卡在寫入這一步 ——
地址是「補得到就好」的東西，不該擋住案件進來。

同樣的想法用在標案關聯：公司、車輛、工務段轄區都是關聯表帶 `is_active`。
換廠商、車輛調度都是常態，但去年的案件仍然要查得到當時是誰在做、哪台車跑的，
所以是停用而不是刪除。

### 設定與機密的分工

```
.env                    所有機密(帳密、金鑰)，開發與部署共用同一份，永不進版控
config/config.dev.yaml  開發用：連哪台主機、排程開關
config/config.prod.yaml 部署用：每個站台一份
```

yaml 裡的機密欄位一律寫成 `${VAR}`，啟動時展開。**缺任何一個變數，後端會列出「缺哪個、對應哪個設定路徑」然後中止** —— 不讓服務帶著空密碼跑起來。

展開後的變數會從 `process.env` 移除，避免機密被子行程或錯誤堆疊帶出去。

### 一張地圖、多個圖層

圖台只有一張地圖，各功能面板把圖層「登錄」進共用的登錄表 ——
所以破壞案件、軌跡、路段、巡查計畫可以任意組合疊看。

「這條軌跡有沒有經過那幾個坑洞」是巡查系統最常被問的問題，
而每個面板各自持有一張地圖的話，這個問題永遠答不了。

點位圖層有三種畫法，對應三種資料量：

| 模式 | 適用 | 為什麼 |
|---|---|---|
| 案件 | 幾百筆以下 | 要看個別案件的類型與狀態 |
| 聚合 | 上千筆 | 點會疊成一片，聚合才看得出哪一區多 |
| 熱點 | 上萬筆 | 連聚合都太密，看的是分布而非個別案件 |

底圖預設用**國土測繪中心的臺灣電子地圖**：台灣的路名與門牌比 OSM 完整，
而且是政府開放圖資、免金鑰。另有正射影像、土地利用、Google、深/淺色共 10 種。

### 向量圖磚

| | GeoJSON | 向量圖磚 |
|---|---|---|
| 大小 | 全區 490 KB | 單格 42 KB |
| 平移 | 每次重載全區 | 只載新的格子，舊的走瀏覽器快取 |

圖磚由 PostGIS 直接產生（`ST_AsMVT`），Node 端只轉手 ——
在應用層裁切幾何是把資料庫最擅長的事搬到最不擅長的地方做。

### WebSocket 不只是推播

同一條連線承擔四種雙向互動：

| 功能 | 資料放哪 | 為什麼 |
|---|---|---|
| 案件討論串 | PostgreSQL | 斷線期間的對話要補得回來 |
| 線上狀態 | Redis(TTL 60 秒) | 行程被強制結束不會有斷線事件，TTL 才不會留下幽靈 |
| 車輛位置回報 | Redis(TTL 2 分鐘) | 位置只有「現在」有價值 |
| 編輯鎖 | Redis(TTL 2 分鐘) | 過期自動釋放，關掉分頁不會把單卡住 |

連線時就驗 token（WebSocket 沒有「每個請求帶憑證」的機制，握手是唯一能擋人的時機），並依公司分房 —— 多租戶下不能把 A 公司的案件推給 B 公司。

### 安全性

- **登入**：帳號鎖定（連續失敗 5 次鎖 15 分鐘）、時間常數化比對（帳號不存在也做一次雜湊，不給時間差）、全域 + 端點級流量限制
- **Token**：HS256 白名單（擋 `alg: none`）、issuer/audience 綁定、`jti`、httpOnly + SameSite=strict cookie
- **輸入**：全域 ValidationPipe（`whitelist` + `forbidNonWhitelisted`，多傳欄位直接 400）、SQL 全參數化、請求體 2MB 上限
- **輸出**：helmet 安全表頭、CORS 白名單、物件儲存只給 5 分鐘簽名網址（bucket 不開公開讀取）
- **稽核**：`@Audit` 只記白名單欄位 —— 稽核日誌長期保存，不該混進密碼
- **過期處理**：401 由全域處理器統一接住（清狀態、回登入頁、說明原因），
  並每 20 分鐘主動續期，讓連續操作的人不會被踢出去

前端把**判斷邏輯全放在 presenters**（顏色、門檻、單位換算），元件只負責畫。於是最有價值的測試不需要 DOM、毫秒級跑完，元件測試只留下「非渲染就驗不到」的少數幾件事。

## 已知限制

- 逆地理編碼是決定性的假實作（正式系統接自架 Nominatim），Demo 不依賴外部服務。
- 行政區界線用案件的凸包近似（正式系統接 NLSC 圖資，那份有幾十 MB）。
- 資料庫備份、推播通知這類需要外部系統的排程，Demo 只做到「算出該做什麼」而不真的送出。
- Google 街景**內嵌**需要 Maps API 金鑰；沒金鑰時走免金鑰的外開連結，或切 Mapillary 內嵌。
- Google 圖磚直接取用 `mt1` 不在其授權範圍內，僅供內部比對；正式站台要改用官方 SDK。
- 沒有 TLS：Demo 走 HTTP，正式站台要補 certbot 與 HSTS。
- 影像上傳只有後端介面，前端尚無上傳畫面。
- 前端只在 Playwright（Chromium headless）驗證過，視覺細節沒有在真實桌機瀏覽器目視確認。
