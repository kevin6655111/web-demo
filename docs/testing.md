# 測試策略

四層，各自回答不同的問題。上層慢但真實，下層快但抽象 —— 兩者都需要。

| 層 | 數量 | 速度 | 回答什麼問題 |
|---|---|---|---|
| 前端單元 | 33 | ~1.5s | 判斷邏輯對不對(顏色、門檻、去重、格式) |
| 後端單元 | 24 | ~1s | 守衛、冪等、回應信封的行為對不對 |
| 端到端 | 54 | ~1m | 整條路徑在瀏覽器裡真的會通嗎 |
| 手動 | — | — | 視覺與地圖互動 |

## 前端：判斷與渲染分開

判斷邏輯全放在 `presenters/`(純函式)，元件只負責畫。

於是最有價值的測試不需要 DOM、毫秒級跑完；元件測試只留下
「非渲染就驗不到」的少數幾件事：無障礙標籤、條件顯示、動畫終值。

```bash
yarn test           # 跑一次
yarn test:watch     # 監看模式
```

**不測樣式與版面** —— 那種測試每次改設計都會壞，卻抓不到真正的問題。

## 後端：守衛與冪等

用假的 Redis 與 ExecutionContext 測守衛與攔截器的行為。
四種冪等情境都各有一個測試釘住：第一次執行、重送回放、內容不同擋下、失敗放鎖。

```bash
yarn test:e2e
```

## 端到端：Playwright

測的是「整條路徑會不會通」——前三層都測不到瀏覽器裡真的發生了什麼。

```bash
yarn test:e2e:browser        # 需要服務先跑起來
yarn test:e2e:ui             # 有介面的除錯模式
yarn test:e2e:report         # 看上次的報告
```

涵蓋：登入與權限過濾、憑證過期自動踢出、導覽、案件查詢與歷程、
**表單（詳情、編輯、派工、管理頁六種新增）**、地圖渲染與工具、圖層疊看、
即時推播（從 API 建案件 → 看瀏覽器有沒有自己更新）、冪等重送。

**登入只做一次**：每支測試各自登入的話，連續失敗 5 次會觸發帳號鎖定 ——
那是系統該有的行為，但會讓整批測試從第六支開始全紅。

失敗時自動留下截圖、影片與 trace：

```bash
npx playwright show-trace e2e-results/artifacts/<測試名>/trace.zip
```

## 這些測試抓到過的真 bug

寫下來是因為它們說明了每一層的價值：

| Bug | 哪一層抓到 | 為什麼下層抓不到 |
|---|---|---|
| BullMQ `jobId` 含冒號 → 派工 500 | 手動 API 測試 | 型別檢查看不出字串格式限制 |
| 全域守衛擋掉微服務事件 → WebSocket 從不推播 | Playwright | 後端單元測試不會跨行程 |
| 側邊欄蓋住內容、蓋住的區域點不到 | Playwright | 沒有真實版面就沒有遮擋 |
| `>>` 有號位移導致路名變成「民生路undefined」 | 手動 + 回歸測試 | 只在雜湊值超過 2³¹ 時發生 |
| MVT 圖磚沒轉投影 → 永遠回空圖磚 | 手動 API 測試 | PostGIS 不會報錯，只是安靜地回空 |
| 圖片檢視器按「放大」卻跳出案件詳情 | Playwright | React portal 沿元件樹冒泡，不是 DOM 樹 |
| 簽名網址用容器主機名，瀏覽器連不到 | 手動驗證簽名網址 | 後端自己打得通，只有瀏覽器打不通 |
| 面板渲染兩次 → 資料抓兩遍、圖層登錄兩遍 | Playwright | 畫面看起來正常，只有網路面板看得出來 |
| 詳情對話框翻頁按了不動 | Playwright | 索引算錯，但沒有任何錯誤訊息 |

最後一項特別值得記住：**不報錯的失敗最難查**。
